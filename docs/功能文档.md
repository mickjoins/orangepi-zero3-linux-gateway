# opiz3-gateway 功能文档

版本：1.0.0
适用硬件：Orange Pi Zero 3（Allwinner H618，四核 Cortex-A53，aarch64）
适用系统：Armbian / Debian / Ubuntu / Orange Pi OS（Linux 5.15+，建议 6.1）

---

## 1. 项目目标

把 Orange Pi Zero 3 配置为一台低功耗嵌入式 Linux 边缘网关，完成以下闭环：

```
系统信息采集 ──────────┐
I2C 温湿度传感器 ──────┤
串口外设数据 ──────────┼──> 共享状态(互斥) ──> HTTP Web 仪表盘 / JSON API
GPIO LED 输出/按键输入 ─┘
```

---

## 2. 功能需求与验收标准

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F1 | CLI 入口 | `--help/--version/--status/--led/--scan-i2c/--simulate/--daemon` 均可用，退出码正确 |
| F2 | 系统监控 | `/api/status` 返回 hostname、uptime、CPU 占用率/频率、内存、SoC 温度 |
| F3 | 传感器采集 | AHT20 读取成功返回 `valid=1` 与温湿度，失败返回 `valid=0`，不导致崩溃 |
| F4 | I2C 扫描 | `--scan-i2c` 能列出总线上 0x03~0x77 的响应设备 |
| F5 | LED 控制 | POST `/api/gpio?state=on/off/toggle` 与 `--led on/off` 能控制 GPIO；支持 active-low |
| F6 | 按键检测 | 默认 button_line 按下一次，`button_pressed_count` 加 1，且 LED 翻转 |
| F7 | 串口按行读取 | 从配置的 `/dev/ttyS1` 按行读取，最新一帧通过 `/api/serial` 输出 |
| F8 | Web/API | 网页 2 秒自动刷新；JSON API 结构稳定，JSON 可解析 |
| F9 | 守护进程 | `--daemon` 可后台运行；systemd 单元可 enable/restart；日志可落 syslog/文件 |
| F10 | 模拟模式 | 在 x86 主机无硬件环境下，F2/F3/F5/F7/F8 均可用 |
| F11 | 交叉编译 | `make CROSS_COMPILE=aarch64-linux-gnu-` 产出 aarch64 ELF |

## 3. 总体架构

### 3.1 进程与线程

```
main()
 ├─ 解析 CLI/配置文件
 ├─ 一次性命令（status/led/scan-i2c）执行后退出
 └─ 服务模式
     ├─ gpio_dev_init()：GPIO 后端初始化 + 按键监控线程
     ├─ collector_thread：每 collect_interval_s 秒采集 sysinfo + sensor
     ├─ serial_thread：阻塞读 UART 行
     ├─ http_server_thread：监听 HTTP 端口
     └─ 主线程等待 SIGINT/SIGTERM 后协调退出
```

### 3.2 数据结构与共享状态

- `system_info_t`：系统信息（`sysinfo.h`）
- `sensor_sample_t`：传感器数据（`shared.h`）
- `app_config_t`：运行配置（`config.h`）
- 所有跨线程数据保存在 `shared.c`，通过 `pthread_mutex_t` 保护。
  线程只负责生产/消费，不直接互发信号量；采集与读取速率低，锁竞争可忽略。

### 3.3 模块依赖

```
main
 ├── config, log
 ├── sysinfo ─────┐
 ├── i2c_sensor ──┼──> shared <── http_server
 ├── gpio_dev  ───┘              ├── gpio_dev（写 LED 时）
 ├── uart_reader ───> shared     └── shared
 └── shared
```

## 4. 关键设计

### 4.1 GPIO 双后端

GPIO 后端按以下顺序自动探测：

1. 字符设备 v1 `/dev/gpiochipN`：
   - `GPIO_GET_LINEHANDLE_IOCTL` 请求句柄；
   - LED 使用 `GPIOHANDLE_REQUEST_OUTPUT`，按键使用 `GPIOHANDLE_REQUEST_INPUT` +
     `GPIOHANDLE_REQUEST_ACTIVE_LOW` + `GPIOHANDLE_REQUEST_BIAS_PULL_UP`；
   - 读/写通过 `GPIOHANDLE_GET/SET_LINE_VALUES_IOCTL`。
2. 字符设备 v2（当 v1 被新内核关闭或返回 `ENOTTY` 时自动尝试）：
   - `GPIO_V2_GET_LINE_IOCTL` 请求句柄；
   - LED 使用 `GPIO_V2_LINE_FLAG_OUTPUT`，按键使用 `GPIO_V2_LINE_FLAG_INPUT` +
     `GPIO_V2_LINE_FLAG_ACTIVE_LOW` + `GPIO_V2_LINE_FLAG_BIAS_PULL_UP`；
   - 读/写通过 `GPIO_V2_LINE_GET/SET_VALUES_IOCTL`（`mask` 置 1）。
3. 回退路径 `/sys/class/gpio`（兼容旧内核/老镜像）：
   - `export` 引脚 → 写 `direction`/`value`（`direction` 使用字符串 `out`/`in`）；
   - active-low 由软件取反。

### 4.2 传感器采集

AHT20/AHT21，I2C 地址 0x38：
1. 读取状态字，只有未校准时才发送完整初始化命令 `0xBE 0x08 0x00`；
2. `write(0xAC 0x33 0x00)` 触发测量，等待 80 ms；
3. 读 7 字节，检查 busy 位 `(data[0] & 0x80) == 0`，最多重试 5 次，并核对 CRC；
4. 按数据手册公式换算温湿度（见 `i2c_sensor.c` 注释）。

### 4.3 串口

- `cfmakeraw`、`CLOCAL | CREAD`、关硬件流控；
- `VMIN = 1, VTIME = 5`；读取函数以约 200 ms 为一次调用的期限，逐字节拼行；
- 遇 `\n` 才返回完整一行（自动剥行尾 `\r`）；未完成的片段跨调用保留，超长行丢弃；
- 串口不可用时 `serial_thread` 直接退出，不对主功能造成影响。

### 4.4 HTTP 服务器

- 纯 POSIX socket 实现，无任何第三方库；
- 有上限地读取请求头，解析请求行与认证头；远程绑定需配置访问令牌；
- 每个连接处理完即关闭（Connection: close），线程模型极简；
- HTML/JS/CSS 以字符串内嵌在二进制中，部署时无需任何静态文件。

### 4.5 模拟模式

`--simulate` 下：
- `gpio_dev.c` 使用内存假后端；
- `make_simulated_sensor()` 生成近似室温正弦/余弦数据；
  - 串口线程每 5 秒生成 `{"sim":1,"seq":...}` 假数据；
- 系统信息仍从主机 `/proc` 读取，这有助于在开发机上观察整套 server/collector 行为。

## 6. HTTP API

### 6.1 GET /

返回内嵌 HTML 仪表盘。页面逻辑：
- 每 2 秒 fetch `/api/status`；
- LED 按钮 fetch `POST /api/gpio?state=...`；
- 显示 hostname、uptime、CPU、频率、温度、内存、传感器、串口、LED、按键计数。

默认仅监听 `127.0.0.1`。如果配置为局域网地址或 `0.0.0.0`，必须同时设置 `http_access_token`；所有 `/api` 请求携带 `Authorization: Bearer <token>`。网页可在提示框输入令牌。

### 6.2 GET /api/status

字段完整版：

| 字段 | 类型 | 来源 |
|---|---|---|
| `app` | string | `version.h` |
| `version` | string | `version.h` |
| `hostname` | string | `gethostname()` |
| `uptime_s` | number | `/proc/uptime` |
| `cpu_count` | int | `sysconf(_SC_NPROCESSORS_ONLN)` |
| `cpu_usage_pct` | number | `/proc/stat` 前后 200 ms 差值 |
| `loadavg` | array[3] | `/proc/loadavg` |
| `mem_total_kb` / `mem_avail_kb` | int | `/proc/meminfo` |
| `mem_usage_pct` | number | `100*(1-avail/total)` |
| `soc_temp_c` | number | 首个可读 `/sys/class/thermal/thermal_zoneN/temp` |
| `cpu_freq_khz` | int | 首个可读 cpu cpufreq `cpuinfo_cur_freq` |
| `sensor` | object | 最近一次 AHT20/仿真数据 |
| `led` | int | 0/1；GPIO 不可用返回 -1 |
| `button_pressed_count` | int | 按键按下次数 |
| `serial_line` | string | 串口最新一行 |

### 6.3 GET /api/sensor

```json
{"valid":1,"temperature_c":28.50,"humidity_pct":63.20,"timestamp":1700000000}
```

### 6.4 GET /api/serial

```json
{"line":"{\"device\":\"demo\"}"}
```

### 6.5 GET/POST /api/gpio

GET 无参数时返回状态。修改状态需 POST、`X-Requested-With: XMLHttpRequest` 请求头，并传查询参数 `state = on | off | toggle`。

```json
{"led":0,"button_current_pressed":0,"button_pressed_count":3}
```

## 7. 错误处理与可靠性

- GPIO 初始化失败仅告警，服务继续运行，所有 GPIO API 返回 `led:-1`；
- 传感器读取失败仅使 `sensor.valid=0`，不会重启进程；
- 串口设备不存在时线程优雅退出，不影响 web 服务；
- `write/read` IO 均检查返回值，日志标注 `strerror`；
- systemd `Restart=on-failure` 保障进程被异常杀死后自动拉起；
- 所有后台线程均以 `shared_is_running()` 作为退出标志；HTTP 客户端读取有期限，停服时可唤醒连接。

## 8. 配置热更新与扩展

当前版本不支持配置文件热更新（为避免运行时 race）。如需热更新，可在 HTTP 服务器做一个
`/api/reload` 并在加锁状态下替换 `g_config`，但 GPIO/串口设备句柄需要重建，建议直接
`systemctl restart opiz3-gateway`。

扩展方向：
- 在 `i2c_sensor.c` 增加 BME280、SHT30 等设备；
- 在 `http_server.c` 增加 MQTT 发布线程；
- 在 `uart_reader.c` 增加 Modbus RTU 解析；
- 在 `gpio_dev.h` 增加 PWM/定时器控制接口。
